## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Use prototype/bootstrap/.taskflow/main.go's "check" pipeline (format -> taskfile fmt:check, test -> taskfile test, lint -> taskfile lint) as the representative W1-like graph: it is the prototype's own self-hosted project driver, matching W1's format-check + unit-tests + static-analysis -> aggregate Check shape. Document its definition file/lines and a stated counting rule (declared flow.Step calls, explicit flow.Needs edges, and non-comment lines of the .taskflow/main.go file).
2. Build the root taskflow CLI (cmd/taskflow) once into a temp bin dir; this is the binary that performs projectdriver.FindRoot + Loader.Build + Loader.Run against prototype/bootstrap's .taskflow package.
3. Write a throwaway bash benchmark script (docs/evidence/t0/raw-w1-startup/benchmark.sh, not a Go file, not under prototype/bootstrap) that times `taskflow list` invocations from within prototype/bootstrap:
   - cold: N samples, each with a fresh empty TASKFLOW_DRIVER_CACHE dir, forcing Loader.Build to run `go build ./.taskflow` every time (removed after each sample);
   - warm: one prewarming invocation populates a fixed TASKFLOW_DRIVER_CACHE dir, then N samples reuse the cached driver binary (Loader.Build short-circuits on the cached binary stat).
   Also capture one single fully-cold anchor sample with `go clean -cache` first (GOCACHE cleared), recorded separately and excluded from the N-sample statistics, since clearing GOCACHE per sample is not representative of normal dev use.
4. Declare N (sample count) up front, run the script, save raw per-sample timings to docs/evidence/t0/raw-w1-startup/{cold,warm}-samples.txt and the single GOCACHE-cold anchor to its own file.
5. Compute median and p95 for cold and warm from the raw samples (sort + selection, documented method).
6. Record machine profile (uname -a, CPU brand via sysctl), macOS build, Go version, mise version, source revision, and explicit cache-state description (driver-cache cold vs warm, GOCACHE state) alongside the results.
7. Write docs/evidence/t0/w1-startup.md: graph description/counting rule, benchmark method, sample count, raw sample links, median/p95 table, machine/toolchain/cache-state facts, and explicit limitations stating this is a single-machine bootstrap-only baseline, not a T1 budget conformance test and not a product/SDK performance commitment.
8. Check off TF-001.03 AC/DoD via backlog CLI, append implementation notes as I go.
9. Re-run `mise exec -- task check` from repo root in the worktree to confirm the benchmark script/evidence files (outside prototype/bootstrap) do not disturb the gate.
