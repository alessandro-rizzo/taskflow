## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Build fixtures/integrity-faults/ as an isolated Go module (own go.mod, like fixtures/t1-benchmark-harness and fixtures/w1/repo) implementing a small, deliberately toy reference snapshot+cache-store - not a spec-only fixture like W2/W3, because AC #1-#3 use falsifiable language ("independently corrupt," "cannot alter," "is rejected before returning success") that only real, runnable code can concretely demonstrate, matching TF-001.04's precedent of instrumenting real code rather than only writing prose/JSON. Explicitly label it a toy reference model, not the future cache-key design, per the ticket's own stable assumption.
2. Implement Snapshot(dir) -> content-addressed digest over sorted file paths + sha256 content hashes, computed once and stored by value - proves AC #2 structurally: a later live-directory mutation cannot retroactively change an already-taken Snapshot's Digest/Files map, since nothing re-reads the live directory after snapshot time.
3. Implement a toy CacheStore with Put/Lookup, storing artifact content and its manifest (digest, size, produced_by_node, produced_by_profile - reusing fixtures/w2/graph.json's manifest.required_fields shape) as independently-verifiable blobs, with instrumented event logging (same loggingStore-wrapper pattern TF-001.04 used) so lookup/reservation ordering can be asserted, not just claimed.
4. Write fault-injection tests demonstrating, independently: (a) corrupted artifact content bytes with an intact manifest -> Lookup detects content-digest mismatch; (b) corrupted manifest metadata with intact content -> Lookup detects manifest mismatch independently of (a); (c) a manifest declaring an output that is actually missing from storage -> Lookup detects missing declared output before claiming success (the "resume output presence" fault, AC #1's third leg); (d) source mutation after Snapshot does not change the snapshot's declared digest (AC #2); (e) for each corruption case, assert via the event log that rejection happens strictly before any success/hit event is emitted (AC #3's "before returning success").
5. Produce evidence: docs/evidence/t1/integrity-faults.md (or fixtures/integrity-faults/README.md's own evidence section) recording identity inputs, lookup/reservation event ordering per scenario, and precise rejection diagnostics/messages (AC #4), plus explicit experimental version per roadmap rule 3a.
6. Verify: go build/vet/gofmt/test on the isolated module; root mise exec -- task check unaffected (own go.mod, not wired into prototype or root).
7. STOP after implementation and verification - do not check AC/DoD or mark Done. Run a codex adversarial peer review of the diff against these ACs and project principles (per the coordinator's standing instruction), then bring the review findings plus the diff back for user approval before finalizing.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Built fixtures/integrity-faults/, a real (toy but runnable, mutation-tested) isolated Go module demonstrating the source-mutation, cache-corruption, and resume-integrity properties E04 needs falsifiable evidence for. Went through one round of independent adversarial Codex review after the first implementation, which found the AC #3 "stale entry" test was not actually testing staleness and that altered-but-present outputs were not detected at all - both fixed and re-verified below.

What was added:
- snapshot.go: Take(dir) returns a content-addressed Snapshot; nothing in the package re-reads the source directory after Take returns, structurally guaranteeing AC #2 (identity-freezing - README is explicit this does not by itself prove an execution consumes frozen content over a live root).
- store.go: a toy in-memory Store with Put/Lookup(identity, currentSourceDigest). Lookup independently verifies, in order: source freshness (Manifest.SourceDigest vs. the caller's current source digest - new, added post-review), content digest, manifest size_bytes, declared-output presence, and declared-output content digest (new, added post-review) - logging a per-call, CallID-scoped Event trail (reserve -> lookup -> verify-* -> reject/success) via the new EventsForCall accessor. A prominent banner (repeated in three places) states the reserve-before-lookup ordering is consistent with TF-001.04's measured prototype, NOT evidence toward E04's opposite-order requirement.
- snapshot_test.go / store_test.go: 10 tests (up from 8). Four independent AC #1 fault tests (content byte-flip, manifest size, missing output, altered-but-present output). The genuine AC #3 demonstration stores an entry under identity X from source snapshot A, mutates source to snapshot B via the real Take mechanism, and shows a lookup of the SAME identity X against current source B is rejected as stale (ErrStaleSource) while lookup-hit still appears in the trail - distinguishing this from an ordinary cache miss, which is kept as its own separate, correctly-labeled test.
- README.md: rewritten with an unmissable top-of-file warning about the reservation-ordering limitation, an explicit clarification of what the snapshot mechanism does and does not prove, the full evidence writeup including all five checks' mutation-testing commands and results, and the two real defects the review caught (with what changed and why).

Tests/verification: go build/go vet/gofmt -l/go test all pass (10/10); root mise exec -- task check green; all five Store.Lookup checks (source, content, manifest, output-missing, output-altered) independently mutation-tested by disabling each guard clause in turn and confirming its corresponding test then fails, then restoring and reconfirming the full suite green.

Not committed: per AGENTS.md's review gate, this is held pending an independent Opus-model verification pass against the original Codex findings, then explicit user approval, before AC/DoD are finalized and the branch is committed.

Update after independent Opus verification: fixed one accuracy issue (N1) it flagged - ManifestSchemaVersion's doc comment claimed enforcement that did not exist. Added a real check (Lookup now rejects a mismatched Manifest.SchemaVersion as its first verification step, ErrManifestSchemaVersion), a proving test, and mutation-tested it (now 6 independently-verified checks, 11 tests total).
