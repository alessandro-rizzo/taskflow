## Description

Roadmap tranche: Risk Lab prerequisite; inputs E01/E02; risks R2 and R10; requirements PLAN-1, PLAN-3, PLAN-4.
Outcome: candidate documents cannot pass validation when known object-shaped or scalar fields have impossible JSON types.
Review evidence: the current validator reports zero violations for a node whose planning condition is a number, resources is a string, execution profile is an array, cache policy is null, and whose artifact type/optional fields are wrongly typed.
Stable assumptions: nested condition/profile/resource/cache object contents remain opaque before Gate 1; this task validates their outer shape and already-declared field types without stabilizing an internal production schema.
Parallelism: independent hardening task. Own fixtures/t1-plan-conformance only.
Test or fault scenario: malformed candidates cover every declared field category and report semantic paths; existing goldens and reordering/digest cases stay green.
Observability: violations include exact JSON-pointer-style paths and expected types.
Rollback or removal: retain negative candidates as frozen regression fixtures.
Versioned formats: bump the experimental harness format only if accepted candidate semantics change incompatibly.

Freeze the reproduced failures as negative plan and schema candidates under testdata: cover every declared envelope, node, artifact, service, secret, effect, operation, argument, and output field category that currently accepts an impossible type, while keeping identifiers/reference arrays otherwise valid so each diagnostic isolates shape validation.

Treat this as a validation bug fix to the already-declared experimental shapes, so do not bump plan/schema format versions unless implementation reveals a previously conformant, well-typed candidate would become invalid.
