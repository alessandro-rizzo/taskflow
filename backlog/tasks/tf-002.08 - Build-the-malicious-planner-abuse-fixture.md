## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Own only fixtures/malicious-planner/ - a new isolated Go module (own go.mod, mirroring fixtures/t1-benchmark-harness's isolation from any root production module), NOT touching fixtures/w1 or fixtures/t1-benchmark-harness's existing files.
2. Catalogue schema (attack.go): an Attempt struct with ID (stable), Category (one of filesystem|environment|network|process|resource|output, covering AC #1's six areas 1:1 with roadmap E03's "Attack fixture attempts" list), Description, ExpectedOutcome (blocked|bounded|trusted_local_limitation - mirroring E03's continue-criteria classification, not a bare allow/deny), ResourceLimit (optional, e.g. a timeout or byte cap), DiagnosticAssertion (what a future real planner-sandbox run should check), and a Run func(ctx) that executes a SAFE, SELF-CONTAINED synthetic version of the attempt today (see step 4). A CatalogueVersion const (e.g. "t1-malicious-planner-v1-experimental") satisfies roadmap rule 3a; a fixture_id "malicious-planner-abuse-catalogue" follows the fixtures/w1 header convention.
3. Result envelope (result.go): one record per attempt run (ID, category, outcome observed, diagnostic text, duration, any redacted-evidence path), plus a suite-level summary; versioned separately from the catalogue itself since results can evolve independently.
4. CRITICAL FRAMING: no planner or sandbox exists in this codebase yet (that's E03's job to build/evaluate) - so "running" this catalogue today is a SELF-TEST of the catalogue's own structure/determinism/non-hanging/non-leaking behavior, not a claim that anything in this repo is secured against these attacks. Every Run func operates only against safe, bounded, synthetic targets it creates itself:
   - filesystem: reads/writes confined to a throwaway t.TempDir()-style directory the run creates and removes; "escape" attempts target a path *inside* that same temp tree standing in for "outside the declared source," never a real system path.
   - environment: reads a synthetic env var this fixture sets itself (never real ambient env vars).
   - network: dials 127.0.0.1 on a closed/unused local port only (net.Listen to find one, then close it before dialing) - never any real external host.
   - process: spawns a trivial child (e.g. `sh -c true`) and immediately waits/reaps it under a short context timeout; asserts no leaked process.
   - resource: bounded, tiny allocations/short loops with an explicit iteration/byte cap and a context deadline - never open-ended growth.
   - output: emits a synthetic "secret" (see step 5) into the attempt's own output and asserts the persisted evidence redacts it.
   Every attempt runs under its own short per-attempt context.WithTimeout (e.g. 2s) AND the whole suite runs under one overall deadline (e.g. 30s), so a bug in the fixture itself cannot hang or genuinely exhaust resources.
5. Synthetic credentials (AC #3): define a fixed, obviously-fake secret marker format (e.g. "SYNTHETIC-TEST-SECRET-<8 hex chars>-DO-NOT-USE", never resembling any real credential format/prefix). Evidence-writing code redacts any substring matching that pattern before writing to disk or stdout. The "output abuse" catalogue entry specifically tries to leak this marker through its own result text, and a dedicated test asserts the marker never appears verbatim in written evidence - this exercises the redaction path against itself rather than only asserting it exists.
6. Runner (cmd/attackcat): a small CLI that runs every catalogue entry's self-test and writes the result envelope to --out, satisfying AC #4 ("one command runs the complete abuse suite in a bounded environment"). Exits nonzero if any self-test errors, hangs past its timeout, or leaks the synthetic secret.
7. Tests (attack_test.go): one test per category asserting the Run func completes within its bound and produces the expected diagnostic; a dedicated redaction test; a catalogue-completeness test asserting all six AC #1 categories are represented and every entry has a non-empty ID/ExpectedOutcome/DiagnosticAssertion (AC #2).
8. README.md: explicit "this is a self-test harness, not a security boundary or a claim about this repository's safety" framing (matching fixtures/w1/w3's honesty pattern), documents the catalogue for E03 to actually run against a real candidate planner sandbox later, and gives the verification command.
9. Verify: go build/vet/gofmt/test on the new module; root `mise exec -- task check` unaffected (isolated module, same as t1-benchmark-harness).
10. STOP after this plan - do not write code until the user reviews it, given the security subject matter.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Built fixtures/malicious-planner/, a versioned attack catalogue and safe self-test harness for docs/roadmap.md's E03 experiment (project-planner trust boundary). No planner or sandbox exists in this repository yet, so this is explicitly a self-test harness proving the catalogue is well-formed, deterministic, non-hanging, and non-leaking - not a claim about any real system's security.

What was built: attack.go (6-entry Catalogue covering AC #1's six categories, ExpectedOutcome using E03's own blocked/bounded/trusted_local_limitation vocabulary), attempts.go (6 Run self-tests), result.go (Redact + versioned result envelope), runner.go (RunSuite with enforced per-attempt/suite timeouts and panic recovery), cmd/attackcat (CLI), attack_test.go (12 tests), README.md.

An independent Codex adversarial review found this was initially NOT safe to run repeatedly: the process attempt inherited the real ambient environment and used PATH-based shell lookup; the network attempt had a close-then-dial TOCTOU race; the environment attempt didn't restore a pre-existing value; timeouts were only checked after synchronous calls returned (a hung attempt would hang the whole suite); no panic recovery existed; and the secret-leak test only scanned one field. All six were fixed:
- process: resolves an absolute, stat-ed known-safe binary path (never PATH lookup) with an explicit minimal environment (never ambient).
- network: dials while the listener is still open (no close-then-dial race) - a successful connect can only ever reach this self-test's own listener.
- environment: captures and restores any pre-existing value of its synthetic env var, not just unset.
- timeouts: runOneAttemptBounded runs each attempt in its own goroutine and selects against the deadline, so a hung attempt is correctly reported timed_out instead of blocking the suite (verified with a deliberately-hanging test attempt).
- panics: recovered, redacted, and recorded as a normal error instead of crashing or reaching stderr unredacted (verified with a deliberately-panicking test attempt that embeds the secret in its panic message).
- secret-leak test: now scans the full serialized JSON envelope, not just one field.

README.md's safety claims were rewritten to describe the actual (fixed) mechanisms precisely, including the one honest residual caveat (a truly hung goroutine can still leak, though RunSuite itself never blocks past its bounds) and an explicit note that attackcat's own --source-revision/--out CLI conveniences are outside the six synthetic attempts' "self-owned resources only" scope.

Verification: go build/go vet/gofmt -l/go test -race all pass; fixture-local and root mise exec -- task check both green. Empirically ran the built attackcat binary end-to-end twice (before and after the fixes), confirming the fixed behavior directly in the JSON output each time, not just via unit tests.

Status: staged, not committed. AC/DoD checked, but ticket status intentionally left off Done pending further independent review, per the project's review-gate process.
