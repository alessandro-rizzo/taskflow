## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Directory and module: fixtures/t1-benchmark-harness/ (own isolated go.mod, matching prototype/bootstrap's isolation pattern - not a root production module, per AGENTS.md/roadmap section 3 rule 2 and section 24 item 8). Location updated per coordinator decision (docs/roadmap.md commit 7d3c91f): fixtures/ now holds T1+ measurement fixtures/harnesses that multiple Risk Lab experiments reuse and that stay frozen once accepted (roadmap section 3 rule 3a), distinct from experiments/'s disposable spikes. Includes a README.md adapted from experiments/README.md's required contents (question, fixture, method, thresholds, limitations, recommendation, one verification command) for a harness rather than a hypothesis experiment.

2. Schema (record.go): a Go struct + JSON encoding, schema_version constant "taskflow-t1-benchmark/v1" (explicit experimental version per roadmap section 2.6 and 3a - no compatibility promise pre-G1). Required fields:
   - schema_version, experiment_id (T0/T1/E01-E08), fixture_id (references a frozen TF-002.01/.02/.03 fixture, e.g. "w1-fast-check@v1")
   - source_revision (git commit), timestamp
   - hardware {cpu, cores, ram_gib}, os {name, version, arch}, toolchain []{name, version} (array - a fixture may involve more than one toolchain, e.g. Go + Xcode for W3)
   - state: enum [cold, warm, cache-hit] - the primary cache dimension under test, satisfying roadmap section 8's literal "distinguish cold, warm, and cache-hit paths"
   - cache_dimensions: optional map[string]string (e.g. {"gocache": "warm"}) - captures secondary cache state so the exact ambiguity TF-001.03 flagged (GOCACHE warm vs TASKFLOW_DRIVER_CACHE cold both mattering) is representable, not lost, without overloading the single required `state` enum
   - samples []float64 (raw wall-clock seconds), sample_count int (redundant with len(samples), validated to match - catches silent truncation/tampering)
   - median, p95 float64 - present in the record but recomputed by the validator from raw samples and rejected if they don't match (protects against hand-edited or mislabeled results)
   - reservation_count *int - required specifically when state == "cache-hit" (directly serves the W1 budget: "zero worker reservations"), optional otherwise
   - raw_result_location: relative path string to raw sample/log files, mirroring the docs/evidence/t0/raw*/ pattern TF-001.01/.03/.04 already used ad hoc

3. Validator (validate.go): Validate(Record) error, with automated tests (validate_test.go) asserting rejection for: missing any required metadata field (one test per field, named errors); empty or non-numeric samples; sample_count mismatched with len(samples); state outside the 3-value enum; median/p95 not matching a fresh recomputation from samples; missing reservation_count when state == cache-hit. Plus a golden round-trip test for one fully valid record. This directly satisfies AC #4.

4. Runner (cmd/t1bench/main.go): a small CLI generalizing TF-001.03's ad hoc raw-w1-startup/benchmark.sh into reusable tooling - takes a command to time, a declared sample count, state, and required metadata as flags, runs the command N times (wall-clock, same method TF-001.03 used), computes median/p95, validates, and writes a JSON record plus raw sample file to a declared output directory. Cold/warm/cache-hit preparation is the CALLER'S responsibility (the runner cannot know what "cold" means for an arbitrary command); the runner requires --state to be declared explicitly and stamps it into the record, while the schema's cache_dimensions field lets the caller declare exactly which caches they cleared/warmed before invoking it - this is what makes preparation "unambiguous": the record states precisely what was and wasn't cleared, rather than trusting an implicit convention.

5. Verification: fixture-local `go test ./...` inside fixtures/t1-benchmark-harness (per repo policy, each experiment/fixture exposes its own verification command), plus root `mise exec -- task check` to confirm the new fixture does not affect the maintained prototype gate (task check only wires prototype:check today, so this should be a no-op check, but confirms no accidental interference).

6. Explicitly out of scope for this ticket: retroactively migrating TF-001.01/.03/.04's ad hoc T0 evidence into this schema (T0 evidence stays as-is; only TF-002.01/.02/.03 and later Risk Lab experiments are expected to adopt this format going forward), and evaluating any result against the roadmap section 8 budgets (no daemon/remote providers exist yet to measure most of them - this ticket only makes results comparable and validated, it does not gate anything against a budget itself).

Both the format (schema/validator, steps 2-3) and the runner (step 4) are in scope per the ticket title and AC - confirmed by coordinator, no split.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Built the T1 benchmark evidence format and reusable runner (fixtures/t1-benchmark-harness/, per the coordinator's fixtures/ layout decision, docs/roadmap.md commit 7d3c91f), the first T1 wave-1 ticket to land infrastructure other T1/Risk Lab tickets will depend on.

What was added:
- fixtures/t1-benchmark-harness/record.go - the Record schema (schema_version, experiment_id, fixture_id, source_revision, timestamp, hardware, os, toolchain[], a required state enum of cold/warm/cache-hit, an optional cache_dimensions map for secondary caches, samples/sample_count, server-recomputed median/p95, reservation_count required on cache-hit, raw_result_location).
- fixtures/t1-benchmark-harness/validate.go - Validate() and ComputeStatistics(), implementing exactly the median/nearest-rank-p95 method docs/evidence/t0/w1-startup.md already used, verified as a known-answer test against TF-001.03's real raw samples.
- fixtures/t1-benchmark-harness/validate_test.go - rejects every required-field omission, malformed/non-finite/negative samples, a sample_count/samples length mismatch, a mislabeled median or p95, an unrecognized state, and a cache-hit record missing reservation_count; plus a JSON round-trip test.
- fixtures/t1-benchmark-harness/cmd/t1bench/main.go - a CLI generalizing TF-001.03's ad hoc benchmark.sh: times N samples of an arbitrary command, auto-detects hardware/OS/toolchain on macOS and Linux (fails closed elsewhere, requiring explicit flags), and refuses to write anything if the resulting record fails validation.
- Taskfile.yml/mise.toml/README.md/.gitignore giving the fixture its own verification command per repository policy.

Why this schema shape: TF-001.03's own evidence already showed a single cold/warm bit is insufficient (Go's GOCACHE and the driver's own build cache were two independent dimensions that both changed timings) - the optional cache_dimensions map makes that declarable instead of collapsed into one field, while the required top-level state enum still matches roadmap section 8's literal wording ("distinguish cold, warm, and cache-hit paths"). Recomputing median/p95 from raw samples rather than trusting declared values, and requiring sample_count to match len(samples), close the "reject malformed/mislabeled" acceptance criterion at the data-integrity level, not just the metadata-presence level.

Explicitly out of scope (per plan and coordinator confirmation): retroactively migrating TF-001.01/.02/.03/.04's T0 evidence into this format (it stays as originally recorded), and evaluating any result against the roadmap section 8 performance budgets (no daemon or remote providers exist yet to measure most of them - this ticket only makes results comparable and valid, it doesn't gate against a threshold).
