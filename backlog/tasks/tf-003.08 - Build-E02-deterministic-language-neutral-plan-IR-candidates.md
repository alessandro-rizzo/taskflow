## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Roadmap experiment: E02; risks R2 and R10; requirements PLAN-1 through PLAN-5.
Outcome: lower an E01 authoring driver into a canonical plan containing no Go runtime values, plus an independent reader with no Taskflow Go imports.
Competing options: canonical JSON; schema-first binary or canonical CBOR/Protobuf with JSON projection if canonicalization proves fragile; bounded dynamic expansion if static shape is insufficient.
Stable assumptions: IR is provisional and disposable; no daemon transport or production type is selected here.
Parallelism: starts once an initial E01 driver exists and may run beside E01 measurement. Own experiments/e02-plan-ir only.
Test or fault scenario: repeated cross-process generation, semantically irrelevant reordering, meaningful condition/profile/output mutations, incompatible versions/unknown fields, large graph, and resume-compatibility diff.
Observability: canonical bytes/digests, generation time/size, semantic diffs, reader output, and conformance evidence.
Rollback or removal: retain incompatible/rejected encodings and generators as evidence until Gate 1.
Versioned formats: every plan envelope and diagnostic projection declares an experimental version.

Phase A - freeze the decision contract before candidate code

1. Create only experiment-contract.md, protocol.json, protocol.sha256, scope hashes, and a contract verifier under experiments/e02-plan-ir. Hash the protocol, verifier/runner bytes, bound inputs, sample counts, thresholds, and rerun rules before any result is collected, correcting E01's explicit runner-hash limitation.
2. Freeze the canonical-JSON candidate grammar and normalization rules before implementation: JSON-only values; no Go functions/interfaces/pointers or secret material; versioned t1-plan-conformance-plan-v2 envelopes; path-aware ordering for set-like declarations and references; exact preservation of meaningful ordered/scalar values; SHA-256 over compact canonical UTF-8 bytes; and a separately versioned e02-resume-diff-v1 diagnostic projection. Keep nested condition/resource/profile/cache semantics explicitly experimental rather than promoting T1's opaque objects into production types.
3. Freeze the evidence scope. W1 must be lowered by a read-only experiment dependency on the accepted E01 candidate B ComposeW1 trace, proving the selected authoring driver reaches plan JSON without editing E01. Because E01 deliberately authored only W1 graph composition and W2/W3 public schema surfaces, define E02-local disposable typed plan fixtures for the W2 and W3 concrete graphs plus the T1 synthetic full-coverage plan; record this boundary as a limitation rather than claiming E01 already supplied executable W2/W3 graphs. Generation may compare with E01/T1 outputs after emission, but must not read goldens as generation input.
4. Predeclare hard gates: all W1/W2/W3/synthetic documents validate and have zero structural diffs against their T1 goldens; synthetic covers typed artifacts, optional output, planning/outcome conditions, resources, profile, cache policy, secret capability reference, endpoint, and effect; 20 fresh processes per fixture emit byte-identical canonical bytes and digests; Go and the independent Python reader compute identical canonical bytes/digests; reordering every declared set-like collection (including top-level declarations, needs/consumes/produces, and declared set-like nested patterns/key inputs) preserves identity; condition, execution-profile, and output type/optionality mutations each alter identity and yield only the predeclared field-level incompatibility paths; incompatible versions and unknown fields fail with stable semantic paths; planning touches no worker/provider/secret value and operation-body/file-write sentinels remain untouched.
5. Predeclare performance and scale gates. Use the T1 benchmark v2 runner with 30 warm, prebuilt fresh-process W1 samples and require p95 strictly below the existing 250 ms cached-plan budget. Generate a deterministic 10,000-node synthetic DAG; require compact canonical plan size at or below 16 MiB, and collect 15 warm fresh-process samples each for generation plus canonicalization and for independent-reader validation plus digest, requiring p95 below 2 seconds for each. Record machine, OS build, Go/Python versions, preparation commands, cache dimensions, raw samples, median, p95, and byte counts. Any failed sample set is retained and rerun only from the start under the frozen rule.
6. Freeze branch/falsification rules without relaxing thresholds: select canonical JSON only if every hard and scale gate passes; if cross-language canonicalization or reorder invariance fails, or correctness requires an open-ended key-name heuristic, retain the failure and pivot to a schema-first Protobuf/canonical-CBOR comparison with JSON diagnostics; if a representative argument-dependent graph cannot become a complete bounded static plan, retain the failure and prototype bounded dynamic expansion with explicit limits, never daemon callbacks into project code; if language neutrality requires erasing typed artifact/optional/endpoint/effect distinctions, stop and revise E01/value semantics before T2.
7. Run the contract-only verifier, present the Phase A diff and threshold table, and obtain explicit approval to commit the contract as a separate pre-implementation commit. Do not add candidate, reader, mutation, or benchmark-result code before that commit exists.
