## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Keep the work fixture-confined and make the minimum shape correction required for real authorization checking: add a non-empty `mobile_e2e_report.consumer_id` to both namespace records, make each endpoint authorization list resolve against that declared in-namespace consumer, and bump the common experimental fixture version from v0 to v1 across spec.md and all eight examples because the new required field is an incompatible example-shape change. Do not define a production provider, plan, wire, or event schema.
2. Extract the dependency-free Python validation logic from the shell heredocs into `fixtures/w3/validate.py`, retaining `validate.sh` as the root-gate entry point. Validate the common envelope and namespace fields with presence-aware type checks: non-empty strings, object/list shapes, positive integer port/TTL values with booleans rejected, unique non-empty string lists, and deterministic field-path diagnostics rather than Python KeyError/TypeError tracebacks. For scenarios, validate only the generic envelope (`scenario`, `description`, object `given`, non-empty object-list `expected_events` with a non-empty string `event`, and string `expected_outcome`); keep scenario-specific event names, payloads, order, outcomes, and provider attestation contents illustrative and opaque.
3. Enforce every relationship already claimed by the namespace fixture: both `produced_by.consumes` links equal the local source id; the service `endpoint_id` equals the local endpoint id; endpoint `target_namespace` and simulator lease `holder` equal the owning `namespace_id`; every authorized consumer resolves to the local report `consumer_id` and no foreign consumer; the report consumes exactly once each of its local endpoint, artifact, and simulator ids; the database path is a normalized absolute descendant of its own writable root; and the namespace-private route marker remains explicit. Validate `profile_attestation` only as an object so E06 remains free to choose its provider contract.
4. Build deterministic global registries over sorted namespace filenames. Reject collisions in namespace ids, service names, ports, normalized writable roots/database paths across namespaces, and all source/endpoint/artifact/simulator/lease/report/consumer ids (including cross-kind collisions). For every failure emit a stable invariant code plus filename, semantic field path, owning namespace, offending value, and the conflicting file/namespace where applicable; sort aggregated diagnostics so output is reproducible.
5. Add `fixtures/w3/test_validate.py` using only the standard library. Copy canonical examples into a temporary directory, apply one named mutation at a time, run the same validator entry point, and assert a non-zero result plus the exact invariant code and contextual diagnostic. Cover missing/wrong typed fields, dangling build/report/service links, foreign endpoint target and lease holder, undeclared/foreign authorized consumers, duplicate report dependencies, service/port/path and every required id-category collision, cross-kind id reuse, database-path escape, malformed scenario envelope, and a positive untouched-fixture case. Keep mutations generated at test time rather than committing invalid golden copies.
6. Update `spec.md` to enumerate the enforced v1 relationships, collision/confinement meaning, stable diagnostic convention, mutation coverage, and exact boundary: this remains a branch-neutral specification validator; it does not attest infrastructure, select an E06/E07 branch, or freeze provider and event payload schemas. Keep example literals illustrative.
7. Verify from the worktree with `python3 fixtures/w3/test_validate.py`, `fixtures/w3/validate.sh`, and, once the worktree mise config is trusted by the integrator, `mise exec -- task t1:w3:check` plus `mise exec -- task check`; run `git diff --check`, append exact results and limitations to task notes, and stop for review before checking AC/DoD, setting Done, or committing.
