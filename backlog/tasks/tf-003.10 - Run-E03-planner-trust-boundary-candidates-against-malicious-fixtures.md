## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Roadmap experiment: E03; risks R3 and R11; requirements SEC-1 through SEC-6.
Outcome: determine whether compiled project code can emit a plan without inheriting daemon filesystem, credential, network, process, resource, or authorization power.
Approaches: restricted native subprocess; pooled minimal sandbox/container; microVM fallback; reduced-execution declarative or generated discovery.
Stable assumptions: the T1 malicious catalogue is a starting set, not proof of safety; the daemon must validate and authorize emitted plans independently.
Parallelism: execution begins after initial E01/E02 drivers exist. Own experiments/e03-planner-trust only; do not modify the frozen catalogue except through a separate follow-up.
Test or fault scenario: external file/env reads, network/socket access, persistent descendants, CPU/memory/fd/output/time exhaustion, secret/unsafe plan fields, parser ambiguity, and privileged capability/effect requests.
Observability: per-attempt blocked/bounded/trusted-local verdict, latency, resource ceiling, sandbox identity, denial reason, and leak scan.
Rollback or removal: sandbox candidates remain disposable; no daemon/provider credential is used.
Versioned formats: policy and result envelopes are experimental and fail closed on unknown versions.
<!-- SECTION:DESCRIPTION:END -->

2. Freeze experimental policy, attempt-result, benchmark, and evidence-envelope versions and fail closed on unknown versions.
3. Freeze the threat model and trusted computing base. Treat compiled project code, its stdout/stderr, and its emitted JSON as hostile; trust only the outer supervisor, kernel or exercised isolation mechanism, immutable bundle builder, and independent validator. Give a planner one digest-verified selected source view plus one declared-input document, a minimal fixed environment, an invocation-private writable temporary directory, and no daemon, provider, Docker, Lima, SSH-agent, keychain, cloud, signing, or secret-store handle. Seed only obviously synthetic daemon/provider/secret canaries in the trusted parent. Every filesystem and socket target is created inside an experiment-owned temporary root, and no real secret or external endpoint is ever used.
4. Freeze a 1:1 E03 attack matrix without editing fixtures/malicious-planner. Preserve its six stable IDs and metadata while replacing the synthetic Run behavior in an experiment-local attack executable: traversal, absolute-path and symlink reads/writes outside the selected view; reads of synthetic ambient credential variables; TCP loopback and Unix-socket access only to listeners owned by the harness; a descendant that tries to persist after planner exit; separately bounded CPU, address-space, file-descriptor, stdout/stderr, and wall-time exhaustion probes; and exact, hex, and base64 synthetic-marker or unsafe-path plan output. Add experiment-local parser/version cases for duplicate keys, trailing documents/bytes, malformed or unsupported versions, unknown fields, excessive document depth/size/counts, and policy cases requesting unauthorized target profiles, network routes, secret capabilities, effects, unsafe paths, or excessive resources.
5. Freeze hard safety thresholds before results: each executable attempt has a 2 second wall deadline and the complete candidate suite a 30 second deadline; CPU hard limit 1 second, address-space hard limit 256 MiB where the mechanism supports it, file-descriptor hard limit 64, combined captured stdout/stderr limit 1 MiB, accepted W1 plan limit 1 MiB, and descendant cleanup verification within 1 second. The selected-source digest and every outside canary must remain unchanged; zero daemon/provider/secret canary bytes or their hex/base64 encodings may appear in planner-visible state or retained evidence; no listener may accept an unauthorized connection; no descendant or post-exit marker may survive; and every case must end as blocked, bounded, or a specifically justified trusted_local_limitation with mechanism identity, applied ceilings, latency, denial reason, and leak-scan outcome. A trusted_local_limitation can document an explicit trusted mode but cannot qualify a candidate for untrusted agent planning.
6. Freeze candidate definitions and comparable boundaries. Native means a fresh process group behind a trusted limit-setting launcher, explicit minimal environment, capped pipes, deadline/kill-group supervision, and a digest-recorded deny-first sandbox-exec profile granting only the selected source, declared inputs, executable/system runtime reads, and invocation temp writes. Pooled container means a prestarted locally built minimal scratch image, no network, read-only root, all capabilities dropped, no host/runtime sockets, 256 MiB/one CPU/pid and fd ceilings, read-only selected-source mount, tmpfs scratch, and one fresh exec per sample. Helper VM is eligible only through an already available and separately authorized dedicated endpoint with equivalent read-only input, network denial, quotas, and cleanup; E03 will not silently create or start host-wide VM state. Reduced execution means a hash-bound E01 schema plus E02 canonical W1 descriptor selected from declared inputs and accepted without running project code; it must disclose that arbitrary dynamic graph construction is unavailable. Installed commands, inaccessible daemons, or unstarted VMs are recorded as unavailable and receive no security or latency credit.
7. Freeze an independent Python 3.9 standard-library validator that shares no planner or E02 Go implementation. It must reject duplicate JSON members, trailing data, malformed/unknown versions, unknown fields, over-limit structure/resources/output, absolute or parent-traversing path-bearing values, targets outside the untrusted W1 allowlist, any unapproved service/network route, any secret request when the policy secret allowlist is empty, and any effect when the policy effect allowlist is empty. It must also require referentially valid effect targets and exact policy identity, accept the known-good W1 plan, and retain stable semantic-path denial diagnostics. T1 conformance remains an additional structural comparison, never an authorization decision.
8. Freeze measurement and evidence rules. Measure each actually exercised candidate from immutable input readiness through independently validated accepted W1 plan using 30 serial warm, prebuilt, fresh-invocation samples and the T1 v2 statistics; pooled mechanisms may exclude one-time pool creation but must include per-invocation admission/exec, output capture, and validation. Pass requires p95 strictly below 0.250 seconds and every sample passing the safety boundary. Bind the wrapper bytes before sampling, retain complete failed/unavailable sets, permit at most one full rerun after a documented mechanical correction, never replace individual samples, and never relax thresholds after observing results.
9. Freeze branch priority. Select native for untrusted/local agent planning only if all hard attack and validator gates pass with no security-relevant trusted-local limitation and warm p95 is below 0.250 seconds. Otherwise select an actually exercised pooled container that passes the same gates and budget; otherwise an actually exercised helper VM that passes them. If executable candidates fail, are unavailable, or miss the budget while the descriptor path passes validation and latency, select static/generated descriptors for untrusted runs and permit only an explicit trusted-local executable mode with its limitations. Stop or narrow the product if the independent validator leaks authority, no approach safely bounds every case, the static form cannot represent the required W1 plan, or every safe approach is incompatible with the planning budget. Correctness and secret leakage failures take precedence over latency and availability.
10. Verify the contract-only boundary with the task-specific check and git diff --check, then stop. Show the complete Phase A diff and threshold table and request explicit authorization to commit the contract and begin Phase B. No attack, candidate benchmark, evidence result, AC/DoD completion, or implementation commit occurs before that checkpoint. Any later contract correction must itself be reviewed and committed before affected attacks restart from the first sample.
