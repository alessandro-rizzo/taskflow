## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Roadmap experiment: E05; risks R6 and R7; requirements CONC-1 through CONC-4 and DUR-1 through DUR-4.
Outcome: simulate whether a shared daemon improves multi-agent utilization without oversubscription, starvation, lost state, or unacceptable operational complexity.
Stable assumptions: fake local, Linux, macOS, simulator, and device providers only; no real builds or production daemon.
Parallelism: first Risk Lab wave beside authoring, sandbox, and macOS feasibility. Own experiments/e05-daemon-simulation only.
Test or fault scenario: 20 mixed agents, competing priorities, saturated finite resources, restarts during admission/execution/cleanup, disconnected clients, authorized attachment, and concurrency-group queue/supersede/cancel.
Observability: resource usage, queue-time distribution, starvation, committed event continuity, orphan/cleanup latency, throughput, install/upgrade complexity, and idle overhead.
Rollback or removal: simulator is disposable and cannot become the T4 daemon implementation.
Versioned formats: simulated state/event/lease envelopes are experimental.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Phase A: frozen experiment contract only

1. Create only contract artifacts under experiments/e05-daemon-simulation: an experimental protocol, workload manifest, decision matrix, fixture-binding manifest, and a contract verifier. Record SHA-256 digests for every Phase A artifact and bind the current W1 manifest, W2 graph, W3 namespace/caller-loss records, and T1 lifecycle fixture versions by digest. Do not add simulator, scheduler, SQLite, evidence-generation, or operational-measurement implementation in Phase A.
2. Freeze this workload before results exist: 20 agents, 10 interactive and 10 background, each submitting one W1-, W2-, and W3-shaped plan in fixed staggered waves for 60 runs total; every client asks for max concurrency 32. W1 specifies three parallel local checks plus aggregation, W2 specifies Linux build then Linux/local fan-out, and W3 specifies Linux service plus macOS build followed by either a simulator or device test and cleanup. Fixed fake capacities are local 4, Linux 4, macOS 2, simulator 2, and device 1. Declare all node service times, arrivals, simulator/device selection, concurrency-group cases, attachment cases, disconnects, crash points, and the 30 tie-order seeds in the workload manifest. Keep every format explicitly pre-Gate-1 and experimental.
3. Freeze the scheduler candidates and scoring rules. Compare a safe independent-CLI baseline whose providers atomically reject over-capacity requests and clients retry after one tick, broker-only central resource leases with client-owned run state, global FIFO, strict interactive priority, and per-agent weighted fair scheduling with a 3:1 interactive/background service ratio plus age promotion. Retain an unguarded independent mode only as a negative control, never as the throughput comparator. Every non-negative mode and seed must have zero provider-capacity violations, zero leaked active leases at drain, and every non-superseded/non-cancelled request terminal. Weighted aging must have zero starved requests, per-class Jain service fairness at least 0.95, maximum ready wait no more than 10 times the longest compatible node service time, interactive queue p95 no worse than FIFO, and background queue p95 no worse than 2 times FIFO. A material scheduling benefit requires at least 15 percent greater completed-node throughput or at least 15 percent lower makespan than the safe independent baseline, plus at least 20 percent lower interactive queue p95 and no greater than a 2 percentage-point utilization regression on any saturated provider.
4. Freeze lifecycle, durability, cleanup, and operations thresholds. Authorized attachment requires exact project, source, operation, arguments, plan digest, namespace policy, and caller-authorization identity, with zero false attachments and at least one duplicate active run avoided. Queue-all, keep-newest-pending, and cancel-superseded-active concurrency cases require deterministic terminal reasons and resource release before an incompatible replacement admission. Admission, execution, and cleanup crash points run before and after commit over 10 seeds, for 60 fresh-process cases, with zero lost or duplicate committed events, zero visible uncommitted transitions, zero sequence gaps/reordering, zero SQLite integrity failures, and zero post-recovery over-capacity admissions. Lease reclamation must finish within one reaper tick after expiry; 30 real disconnect/reopen samples must have cleanup p95 at most 1 second and maximum at most 2 seconds. Thirty warm controller startup/reopen samples must have p95 below 250 ms. A 30-second quiescent sample must have idle CPU p95 below 1 percent, RSS p95 below 40 MiB, clean stop below 1 second, one resident process, one state directory, no external service, and no manual pre-run start for the on-demand path.
5. Freeze requirement scope and branch precedence. The current canonical mapping is AGENT-2 through AGENT-5, EXEC-2, EXEC-3, EXEC-5, DUR-1, and DUR-3; AGENT-4 is exercised only for namespace/lease ownership, not filesystem or service isolation, and the experiment makes no claim for AGENT-1, AGENT-6, or DUR-2. The ticket references to CONC-1 through CONC-4 and DUR-4 are stale and create no aliases. Select stronger state on any SQLite durability hard-gate failure; stop if no shared/broker candidate satisfies safety, fairness, and cleanup; select full daemon only when weighted fairness passes all gates, meets the 20-agent material-benefit thresholds, regresses one-agent makespan by at most 5 percent, and meets all always-on budgets; select on-demand daemon when the hard gates and 4/20-agent material benefit pass but single-agent or always-on cost misses; select broker-only when it passes safety/reclamation, reaches at least 95 percent of full-daemon throughput with queue p95 within 10 percent, and centralized run ownership contributes no unique passing durability/attachment result; otherwise select stop/narrow rather than relaxing thresholds after results.
6. Implement the Phase A verifier only. It must reject missing or extra contract sections, wrong workload counts/capacities/seeds, incomplete candidate or threshold definitions, stale fixture digests, internally inconsistent decision precedence, non-experimental versions, or any Phase B simulator/results artifact present prematurely. Run the contract-only verification command and git diff --check. Then stop, show the Phase A summary and complete diff, and wait for explicit approval. Commit the frozen Phase A contract separately only after explicit commit authorization. Do not begin Phase B until that accepted contract commit exists.

Phase B: simulator, fault execution, evidence, and decision after the accepted Phase A commit

7. Implement a dependency-free Python discrete-event simulator inside the claimed experiment directory. Model provider capacity, reservation, disposable sandbox, and session lease as distinct lifecycles; reserve multi-resource requests atomically; ensure capacity-wait work consumes no execution slot; implement all frozen scheduling, attachment, concurrency, and disconnect cases; and emit normalized JSONL after every durable state/resource change. Do not import prototype or fixture code and do not execute real builds.
8. Add the real disk-backed SQLite adapter through Python sqlite3 with foreign keys enabled, WAL journal mode, FULL synchronous commits, and one experimental schema version. Clearly limit the result to returned-commit plus process-death evidence, not power-loss hardware durability or a production database API.
