## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
OPEN QUESTION for user before implementing (see report): where does a T1 cross-experiment fixture tree live? Proposal: new top-level fixtures/ directory (fixtures/w1/), since it doesn't fit docs/ (not a decision), experiments/eNN-*/ (not one question with a deadline, and experiments/README.md bans even experiments from importing prototype/bootstrap - inapplicable here anyway since this fixture doesn't need to), or prototype/bootstrap/ (frozen, not to be extended). This does extend roadmap section 3's repository layout, so flagging for explicit confirmation rather than deciding unilaterally.

1. fixtures/w1/repo/: a minimal standalone Go module (own go.mod) - not wired through prototype/bootstrap's flow/engine and not a Taskflow-authored pipeline (no SDK exists pre-Gate-1). This is the target repo that a future authoring experiment (E01) points a pipeline at, matching roadmap section 8 deliverable #1 ("minimal repositories... for W1"). Contains: a small package with normal source + one unit test, deliberately simple.
2. fixtures/w1/repo-format-failure/, repo-test-failure/, repo-lint-failure/: minimal variant copies that each fail exactly one of the three W1 checks (gofmt-dirty, failing test, vet-triggering issue), for the "format failure / unit-test failure / static-analysis failure" fault scenarios (AC #1). Each variant is otherwise identical to the base repo so only one dimension differs.
3. fixtures/w1/manifest.yaml: machine-readable declaration - fixture_id, roadmap_workflow: W1, version: t1-experimental-v1 (satisfies "versioned formats"), expected nodes (format, test, lint, aggregate Check), expected edges (format/test/lint -> Check), planning conditions (e.g. test node re-plans only when *_test.go or its package changed - satisfies "planning conditions based on changed paths"), expected outputs (test report shape), expected diagnostics per fault variant (AC #2).
4. fixtures/w1/README.md (fixture specification, human-readable twin of manifest.yaml): explains the three variants, and defines cold/warm/ready-cache-hit as external PRECONDITIONS on cache/driver state (not fixture content) so state can be selected without editing the fixture (AC #3) - modeled on TF-001.03's TASKFLOW_DRIVER_CACHE pattern (external cache dir empty vs warm vs pre-seeded with a known result).
5. Explicitly declare the "ready cache-hit requires zero worker reservations" property (AC #4) as a TARGET/golden expectation this fixture asserts for any future implementation to be measured against - explicitly NOT a claim that the current prototype meets it (TF-001.04 proved the opposite: acquisition always precedes cache resolution today). Word this carefully so the fixture reads as a measurement contract, not a passing test of prototype/bootstrap.
6. Do NOT invent a benchmark-result schema here (TF-002.04 owns that) - just note in manifest.yaml/README.md where this fixture's expected-output declarations are meant to plug into that format once it exists.
7. Verification: gofmt/go vet/go test manually run against each variant to confirm each fixture actually fails exactly the intended single check and the base repo passes all three cleanly. Record commands and results as evidence (measured facts vs. limitations vs. open questions, matching T0's evidence style) in fixtures/w1/README.md or a small evidence subsection.
8. Root `mise exec -- task check` must remain green throughout (fixtures/ is inert to it - no root Go module exists yet).

STOP after this plan is written - do not create fixture files yet. Awaiting user approval, in particular on the fixtures/ location question.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Froze the W1 fast-project-check fixture under the new fixtures/ top-level directory (docs/roadmap.md section 3 rule 3a).

What was added:
- fixtures/w1/repo/ - minimal standalone Go module (its own go.mod, one function, one test) representing the target repo W1 experiments plan/execute against. Not a Taskflow-authored pipeline (no SDK exists pre-Gate-1) and does not import prototype/bootstrap.
