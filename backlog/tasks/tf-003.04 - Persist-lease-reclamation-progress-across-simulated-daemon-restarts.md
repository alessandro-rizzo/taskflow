## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Roadmap tranche: Risk Lab prerequisite; input E05/E07; risks R6 and R7; requirements DUR-1, DUR-3, NS-5.
Outcome: lease expiry and orphan reclamation can resume from durable state after reconstructing a fresh manager, not only by reusing the same in-memory LeaseManager.
Review evidence: the current crash-during-reclamation test calls ResumeReclamation on the same manager, so reclaimStage survives only in memory while the README describes a restart.
Stable assumptions: the fixture may define its own experimental snapshot format and does not choose the future daemon database.
Parallelism: independent hardening task. Own fixtures/t1-lifecycle-faults lease persistence and its tests/docs only.
Test or fault scenario: crash before and after each reclamation-stage commit, serialize durable journal and lease state, reload a distinct manager, then finish exactly once.
Observability: evidence distinguishes persisted stage, resumed stage, duplicate suppression, and final inactive state.
Rollback or removal: retain the restart round-trip as an E05 regression fixture.
Versioned formats: lease snapshot/state format is explicitly experimental and versioned.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Define a fixture-local, explicitly experimental lease-state envelope in a new `fixtures/t1-lifecycle-faults/lease_state.go`, with its own format-version constant. Snapshot the logical clock and every lease field required for expiry/reclamation (`id`, namespace/resource identity, TTL, acquisition/renewal ticks, active state, and committed reclamation stage) in deterministic lease-ID order; keep the journal as its existing separate durability boundary and do not introduce a database or production API.
2. Add a strict `LoadLeaseManager` path that constructs a new manager and fresh lease objects from bytes plus the separately reloaded journal. Reject malformed/trailing JSON, missing or incompatible versions, unknown fields, duplicate/blank lease identities, invalid TTL/time relationships, out-of-range or impossible reclamation stages, and disagreement between the saved stage and the journal's ordered committed reclamation prefix. Return no partially usable manager on error.
3. Replace the first-stage-only reclamation fault seam with a named-stage fault selector that can crash immediately before or after each entry in `reclaimStages`, while preserving the ordinary no-fault expiry path. Keep progress advancement ordered after the journal commit so a saved stage denotes the exact committed prefix.
4. Expand `scenario_lease_expiry_test.go` with a table over all four reclamation stages and both fault timings. For every case, snapshot both journal and lease state after the injected crash, reload both into distinct objects, resume on the fresh manager, and assert the canonical event sequence appears exactly once, no stage is skipped, persisted progress is observable, and the lease finishes inactive. Add a separate round-trip/no-shared-memory test covering clock and ordinary lease fields, plus table-driven malformed, incompatible, internally inconsistent, and journal/state-mismatch rejection tests.
5. Update the fixture README to name the new lease-state format and distinguish: journal durability preserves committed events; lease-state durability preserves clock/lease/reclamation progress; the test uses deterministic logical ticks and in-memory byte snapshots and therefore does not prove wall-clock TTL accuracy, fsync/crash atomicity, multi-record transactions, or suitability of any storage engine. Record the corrected guarantee and remaining E05 limitations without changing the package-wide scenario version unless the implementation introduces an incompatible scenario-semantic change.
6. Format and verify with `go test ./...` and `go test -race ./...` in the fixture, then run repository-root `mise exec -- task t1:lifecycle-faults:check`, `mise exec -- task t1:lifecycle-faults:race`, `mise exec -- task check`, and `git diff --check`.
