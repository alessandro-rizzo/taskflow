# ADR 0004: T1 exit — measurement contracts and representative fixtures

Status: accepted

Question: does T1 (measurement contracts and representative fixtures)
satisfy its exit gate, and may the Risk Lab experiments (E01-E08) begin
against T1's fixtures once each experiment's own further prerequisites are
met?

Decision date: 2026-09-03

Task: TF-002.09. Roadmap references:
[T1 deliverables and exit gate](../roadmap.md#8-t1-measurement-contracts-and-representative-fixtures),
[Risk Lab experiments](../roadmap.md#9-risk-lab-experiments),
[decision-record fields](../roadmap.md#21-decision-records).

## Context

TF-002.01 through TF-002.08 independently built T1's fixtures and harnesses
at source revision `279fe00` (macOS/arm64, Go 1.25.12): frozen W1/W2/W3
fixtures, the benchmark evidence format and runner, a plan-schema
conformance harness, lifecycle fault injectors, integrity/source-mutation
fault fixtures, and the malicious-planner abuse catalogue. Unlike T0 (pure
measurement of an existing prototype), T1 is design/build work, so every
ticket went through an additional layer of scrutiny beyond what T0 used:
independent Codex CLI adversarial review, one or more fix rounds, and
independent Opus-model verification of each fix before acceptance. Two
tickets (TF-002.06, TF-002.08) were initially rejected outright by their
Codex review ("does not meet" / "not safe to run repeatedly") and only
passed after real mechanism-level fixes, not just documentation changes —
this is stronger evidence than T0 had, and this decision treats it as such.

This is a gate decision about T1's *fixtures and harnesses*, not a product
design decision. It makes no claim about what E01-E08 will conclude, and it
does not authorize any Risk Lab experiment to skip its own stated
prerequisites (e.g. E03 needs a chosen sandbox mechanism before its full
attack suite has a real target; E06 needs reserved macOS infrastructure).

## Options considered

1. **Pass T1 unconditionally** — accept all eight fixture/harness tickets
   and declare every E01-E08 experiment unblocked to start immediately.
2. **Pass T1 with named residual gaps recorded, not blocking** — accept the
   evidence, but explicitly record every gap the multi-round review process
   surfaced (see "Residual gaps" below) as accepted, bounded limitations
   rather than silently dropping them.
3. **Fail or narrow T1** — require further fixture work before any
   experiment may begin.

## Predeclared thresholds

From roadmap section 8, T1 passes when every Risk Lab experiment can run
against a representative fixture, report comparable results, and
distinguish cold, warm, and cache-hit paths. From this ticket's own
acceptance criteria, that decomposes into four checks, evaluated below.

## Residual gaps (accepted, not blocking)

Each fixture's multi-round review left a small number of documented,
non-blocking limitations. Recording them here so they are not lost, per the
same reasoning TF-001.05's G0 decision used for T0's residual gaps:

- **TF-002.05**: the schema-conformance side covers W1 only with a
  non-empty `arguments` example (W2/W3 schema goldens still have empty
  `arguments`); one type-assertion pattern (`idOf`) remains structurally
  similar to the fixed canonicalization bug but is fully shadowed by
  validation for every field it governs, so it cannot produce a wrong
  digest for any document the harness currently accepts.
- **TF-002.06**: the worker-loss downstream-ordering assertion pins the
  scenario's own recorded call sequence rather than enforcing a
  production-side invariant; this is a legitimate reading of "fixture" per
  Opus's review, not a defect.
- **TF-002.07**: the toy `CacheStore`'s reservation-before-lookup ordering
  intentionally matches the prototype's known (E04-opposite) behavior as an
  explicitly-labelled baseline, not a target — this is by design, not a gap,
  but is listed here because it is easy to misread out of context.
- **TF-002.08**: the CLI's own `--source-revision`-omitted fallback shells
  out to real ambient `git` (PATH-resolved, real environment) — this is a
  documented, intentional exception to the six synthetic attempts' isolation
  guarantee, scoped to the CLI wrapper, not the attack catalogue itself.

None of these were rated blocking by any review round.

## Decision

**T1 passes.** All four exit criteria hold, evidenced by real, independently
reproduced runs, not only unit tests. Every Risk Lab experiment E01-E08 has
at least one representative fixture and a comparable result path through
`fixtures/t1-benchmark-harness`.

**Next allowed parallel Risk Lab work**: per `docs/decisions/0003-g0-t0-exit.md`'s
existing E01-E08 ownership table (owner, bounded `experiments/eNN-slug/`
path, dependency statement, start wave), which this decision does not
revise. That table already conditioned every experiment's start on T1
landing; T1 has now landed, so wave 1 (E01, E04, E05, E06-inventory) may
begin, followed by wave 2 (E02, E03-execution) once an initial E01 driver
exists, followed by wave 3 (E07, E08) once E06 has an initial shape.

## Consequences and deliberately unsupported cases

- This decision does not certify that any experiment will reach a
  "continue" branch — it certifies only that each experiment now has
  representative, comparable, fault-aware inputs to run against.
- This decision does not initialize a root production Go module, and does
  not authorize one. Per roadmap section 3 rule 2 and section 24 item 8,
  that still waits for Gate 1.
- This decision does not claim Linux/amd64 reproducibility for any fixture;
  all verification here is macOS/arm64-only, consistent with T0's own
  limitation.
- The four "residual gaps" above are accepted as-is; revisiting any of them
  requires new evidence, not just re-opening the discussion.

## Trigger for revisiting this decision

- A Linux or amd64 reproduction of any T1 fixture's gate fails where
  macOS/arm64 passed.
- An E01-E08 experiment discovers its assigned fixture is not actually
  representative of the workflow it claims to cover (e.g. E08 finds
  `fixtures/w2/` omits a protocol concern its spike needs).
- Any of the four "residual gaps" above turns out to matter in practice for
  an experiment's conclusions.

## Contracts now allowed to stabilize

None. No plan, schema, cache, provider, or SDK contract stabilizes at T1
exit — that still waits for Gate 1, after E01-E08 converge. T1's own
fixture/harness conventions (`fixture_id`/`version`/`status` header;
`fixtures/t1-benchmark-harness`'s record schema `taskflow-t1-benchmark/v2`)
remain pre-Gate-1 experimental formats per roadmap section 3 rule 3a, and
may still change incompatibly if a Risk Lab experiment finds they don't fit.
