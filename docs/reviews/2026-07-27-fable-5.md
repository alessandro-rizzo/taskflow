# Fable 5 adversarial review of `d3a7732`

Claude Code 2.1.220 ran this review with `claude-fable-5` at maximum effort.
The reviewer was restricted to repository reads. Its Git/Bash allow-list did
not activate, so it reviewed the complete tree at `d3a7732` rather than
executing tests or mechanically comparing the parent diff. Taskflow's
maintainer subsequently reproduced findings and ran the test suite.

## Findings and disposition

### Critical

1. **Cross-target dependency outputs were not transferred. — Fixed.**
   Dependency manifests only affected downstream cache keys. Runtime execution
   now restores each dependency artifact before a cache miss executes.
   Output-producing cache-off/read-only steps publish under run-scoped keys.

2. **Early `io.Pipe` consumer failure could deadlock publication or source
   materialization. — Fixed.** Both consumers now close their pipe reader
   before waiting for the producer. Regression tests use producers that cannot
   finish unless they observe `ErrClosedPipe`.

3. **Archive symlink `..` could escape the workspace. — Fixed.** Archive names,
   resolved link targets, existing parent components, and member ordering are
   validated. Extraction replaces symlinks idempotently, strips special mode
   bits, and will not traverse an existing or archive-created symlink parent.

4. **SSH path components accepted `.` and `..`, allowing cleanup outside the
   generated workspace. — Fixed.** Dot-only components are hashed, the resolved
   workspace is independently checked below the configured non-root directory,
   and flow definitions reject dot-only step IDs and execution groups.

5. **Resume invalidation was not transitive. — Fixed.** If a successful node
   cannot retain its artifact, every succeeded transitive dependent is reset.
   Per-invocation retry counters and stale result identity are reset too.

### High

1. **Corrupt/torn cache entries failed execution instead of behaving as
   misses. — Fixed.** Invalid metadata, key, size, or content manifests produce
   a cache miss. Actual filesystem I/O failures remain errors.

2. **Driver fingerprints ignored imported project packages and embedded
   files. — Fixed.** The loader uses `go list -deps -json` and hashes build
   inputs for every package in the main module, plus module/workspace files.
   Local replacement modules remain an explicit limitation.

3. **Cleanup failure converted completed work into failed work. — Fixed.**
   Cleanup errors after successful execution/cache publication are persisted
   and emitted as warnings without changing the successful step result.

4. **Concurrent local steps shared a mutable workspace and could poison output
   archives. — Fixed within the declared-output model.** Cacheable and
   output-producing local steps receive exclusive workspace admission.
   Concurrent steps with no declared outputs remain the fast shared path;
   undeclared writes remain outside Taskflow's correctness contract.

### Medium

1. **Retries could wait behind unrelated long work. — Fixed.** The running-step
   select now also wakes at the next retry deadline.

2. **Resume retained spent retry attempts and stale output identity. — Fixed.**

3. **`state.Apply` mutated the caller's map before durable append. — Fixed.**
   Public application is copy-on-write; replay retains its linear in-place
   path.

4. **SSH and local archive pattern/determinism semantics differed. — Fixed.**
   SSH produces a sorted no-recursion tar stream which the controller validates,
   filters with Taskflow patterns, and normalizes before storing.

5. **Remote tar extraction bypassed Taskflow validation and preserved unsafe
   modes. — Fixed.** Uploads are normalized and validated before reaching
   remote `tar`; special permission bits and ownership metadata are removed.

6. **Symlink restoration was not idempotent. — Fixed.**

7. **Admission errors returned before journaling final state. — Fixed.**
   Admission failures become durable failed-step transitions and flow through
   normal run termination.

8. **Task/Just cache identity did not observe the installed runner version. —
   Fixed.** Those adapters contribute automatic `--version` probes. Direct
   commands still require explicit toolchain declarations where relevant.

9. **CLI cancellation bypassed graceful journal/cleanup behavior. — Fixed.**
   CLI and driver install interrupt/termination contexts; the loader forwards
   cancellation and gives the driver a bounded grace period before killing it.

### Lower-severity observations

- Provider capability/reservation calls can stall scheduling if extensions
  perform network I/O synchronously. The public contract now requires cached,
  non-blocking implementations; a future provider harness should enforce this.
- Structural/full digests lacked a schema version. Both now include one.
- Driver protocol mismatch guidance incorrectly suggested rebuilding. It now
  tells users to align CLI and project SDK versions.
- Run IDs ending in `.lock` collided with the file store's lock namespace.
  They are now rejected.
- The repository's guarded check now runs the race detector.

## Test gaps called out by the reviewer

The remediation adds tests for hostile tar paths and symlinks, deterministic
archives, early pipe failure, transitive resume, retry wakeups, durable
admission failure, pre-commit snapshot isolation, hostile SSH components,
remote archive validation, imported driver dependencies, driver cache reuse,
local exclusive admission, graceful subprocess interruption, and real
cross-target artifact transfer.

The following remain intentionally incomplete:

- a production Sprite provider and provider-fault integration harness;
- a single immutable source snapshot captured once per run;
- recursive driver hashing across local `replace` modules;
- distributed journal/object-store lease and corruption tests;
- execution-group lifecycle and garbage collection for retained remote
  workspaces.
